# LabWeft 开发交接

[English](HANDOFF.md)

## 已确认的产品选择

本地优先。由用户已有的 coding agent 控制流程。用户使用一个对话，无需自行操作多个 agent。工具协议尽量不绑定模型或服务商。科研项目身份稳定，并与仓库、分支和路径分离。以小型核心、Skill 入口、持久证据和可点击地图组成产品。用户记录与工具源码分开保存。默认不启动训练、不改研究代码、不公开上传，也不迁移数据集。

事实、解释、人工决策与适用范围分开存储。已核实的历史结论（例如有边界的硬件检查）约束后续建议。新 seed 是重复验证；配置外观相同不等于重复实验的证明。保留未知项、人工纠正和旧快照。科研发现可以是负结果；不强制要求填满完整的因子实验表。

## 已实现模块

- `store.py`：项目身份、不可变文本 blob、事件重放、本地锁、revision 冲突、schema/引用检查，以及保护人工修正的约定。
- `scan.py`：保守清单与 Python 静态符号索引；JSON/TOML/CSV 读入；不执行来源代码，也不编造历史 commit。
- `reasoning.py`：描述性 seed 比较、来源漂移、范围内适用性检查。
- `server.py`：带 token 的只读 loopback 服务及安全的离线导出。
- `cli.py`、`rh.py`、`bootstrap.py`：简洁的命令入口和 Skill 安装。
- `static/`：可展开地图、关系视图、比较矩阵、决策、证据/历史；已有中英文静态界面及更新时间线。
- `skill/`：单控制者流程和语义补丁约定。
- `tests/`：确定性回归测试；`demo.py`：合成示例。

## 下一步应做什么

先在同一个真实仓库、相同模型、权限和来源材料上，对比普通 Codex、Codex + EvoSkills 与这个 Skill。先评价初始重建，再在结果变化后的新会话评价持续更新。尚无测量结果时不能声称哪种方法更优。需要同时调查误报“重复实验”和错误豁免本来必要的实验。

扩大范围前，修复这些案例暴露的问题：原始文件丢失但用户已确认的硬件结论、实验目录重命名、新独立 seed、有效 batch/精度/协议改变、过期结果目录、共享 baseline、自定义 YAML 配置、多仓库研究身份、重复扫描与保留人工修正。增加轻量级未来运行记录，减少历史缺口，但不要求追溯性重训。

随后改善常见实际来源布局的适配器、被中断长扫描的持久 job 检查点、记录迁移、来源身份协调、组件级 UI 编辑，以及现有双语界面的可访问性。多项目主页与跨 agent 兼容性测试应先于可选远程适配器。

不要把另一个聊天产品、GPU 调度器、模型网关、插件市场、十种消息平台、向量数据库或公网托管作为起点。

## 发布门槛

确认名称/命名空间及权属，审查许可证和未来可能引入的第三方代码。确保 README 示例能在干净克隆中运行，记录操作系统/浏览器/agent 的兼容矩阵。准备获准公开的真实项目回归材料，或忠实的合成替代。发布包不得包含私有项目快照、凭据或隐藏路径。来源/决策变化应可追溯，基准协议及已知限制应公开。在任何集成前核对已确认的 GitHub 仓库；对外发布按用户授权执行。
